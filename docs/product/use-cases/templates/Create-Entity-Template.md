## User Goal
Пользователь создает новый объект сущности для хранения и дальнейшего использования в системе.
## Actor
Пользователь (User)
## Trigger
Пользователь инициирует создание объекта сущности через интерфейс системы.
## Preconditions
- PRE-1 Пользователь аутентифицирован.
- PRE-2 Пользователь находится в интерфейсе управления объектами сущности.
## Postconditions
- POST-1 Success Guarantee: Объект сущности создан и сохранен в системе.
- POST-2 Minimal Guarantee: В случае ошибки состояние системы не изменяется.
## Main Scenario
1. Пользователь выбирает операцию создания объекта.
2. Система отображает форму создания.
3. Пользователь вводит данные.
4. Пользователь подтверждает сохранение.
5. Система валидирует данные.
6. Система сохраняет созданный объект сущности.
7. Система отображает созданный объект.
## Alternative Scenarios and Extensions
- 3a. Отмена создания (на шагах 3-4)
1. Пользователь отменяет создание объекта до подтверждения сохранения.
2. Система прекращает выполнение сценария.
3. Новый объект не создаётся.
- 5a. Нарушение бизнес-правил
1. Система обнаруживает нарушение бизнес-правил.
2. Система отображает сообщение об ошибке.
3. Возврат к шагу 3.
## Exceptions
E1 Системная ошибка (на шаге 6)
1. Происходит технический сбой при сохранении данных.
2. Система фиксирует ошибку.
3. Система отображает сообщение о невозможности завершить операцию.
4. Сценарий завершается.
## Business Rules
BR-0 Пользователь может управлять только своими объектами.  
Бизнес-правила для объектов конкретных сущностей определяются в соответствующих сценариях.
## Notes
Данный сценарий является шаблоном для операций создания объектов системы (траектория, навык, действие).
