## User Goal
Пользователь изменяет данные существующего объекта и сохраняет изменения.
## Actor
Пользователь (User)
## Trigger
Пользователь инициирует редактирование объекта сущности через интерфейс системы.
## Preconditions
- PRE-1 Пользователь аутентифицирован.
- PRE-2 Пользователь находится в интерфейсе управления объектами сущности.
## Postconditions
- POST-1 Success Guarantee: Измененные данные объекта сохранены в системе.
- POST-2 Minimal Guarantee: В случае ошибки состояние системы не изменяется.
## Main Scenario
1. Пользователь выбирает операцию редактирования объекта.
2. Система отображает форму редактирования с текущими данными объекта.
3. Пользователь изменяет данные объекта.
4. Пользователь подтверждает сохранение.
5. Система валидирует данные.
6. Система сохраняет изменения.
7. Система отображает обновлённый объект.
## Alternative Scenarios and Extensions
- 3a. Отмена редактирования данных (на шагах 3-4)
1. Пользователь отменяет редактирование.
2. Система прекращает выполнение сценария.
3. Изменения объекта не сохраняются.
- 5a. Нарушение бизнес-правил
1. Система обнаруживает нарушение бизнес-правил.
2. Система отображает сообщение об ошибке.
3. Пользователь корректирует данные.
4. Возврат к шагу 4.
## Exceptions
E1 Системная ошибка (на шаге 6)
1. Происходит технический сбой при сохранении данных.
2. Система фиксирует ошибку.
3. Система отображает сообщение о невозможности завершить операцию.
4. Сценарий завершается.
## Business Rules
BR-0 Пользователь может управлять только своими объектами.  
Бизнес-правила для объектов конкретных сущностей определяются в соответствующих сценариях.
## Notes
Данный сценарий является шаблоном для операций редактирования объектов системы (траектория, навык, действие).
